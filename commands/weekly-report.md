주간업무보고서를 작성해주세요. 아래 절차를 따릅니다.

## 1단계: 보고 기간 결정

- 인자가 있으면 해당 주를 기준으로 합니다: $ARGUMENTS (예: "2026-03-23" → 해당 주 월~금)
- 인자가 없으면 이번 주 월요일~오늘(또는 금요일) 기준으로 합니다
- 보고 기간을 "MM/DD(월) ~ MM/DD(금)" 형식으로 표시합니다
- **주말(토, 일) 작업은 그 다음 주 보고서에 포함합니다.** 즉, 이번 주 보고서의 수집 범위는 "직전 주 토요일 ~ 이번 주 금요일"입니다. (한국시간 KST 기준)

## 2단계: 직전 보고서 참고

`/Users/pullim/Documents/workspace/주간업무보고/` 폴더에서 가장 최근 보고서 파일(`YYYY-MM-DD.md` 중 최신)을 읽어 다음을 파악합니다.

- 직전 주의 "차주 업무 내역" — 이번 주에 실제 어떻게 진행됐는지 대조
- 직전 주의 "진행 중인 업무" — 이번 주에 완료·지속·중단 중 어느 상태인지 확인
- 보고 톤·표현 일관성 유지를 위한 참고 (같은 업무를 새 업무처럼 다시 적지 않도록 주의)

폴더가 비어있거나 파일이 없으면 이 단계를 건너뜁니다.

## 3단계: Git 이력 수집

아래 workspace 내 모든 git 프로젝트에서 보고 기간의 커밋을 수집합니다.
각 프로젝트 디렉토리에서 병렬로 실행하세요:

```
TZ=Asia/Seoul git log --author="sangjun-lim" --since="<직전 주 토요일>" --before="<이번 주 토요일>" --format="%h %ad %s" --date=short
```

대상 디렉토리: /Users/pullim/Documents/workspace/ 하위의 모든 git 저장소

## 4단계: 커밋 분석 및 업무 분류

수집된 커밋을 분석하여 다음 기준으로 업무를 분류합니다:
- 프로젝트별로 그룹핑
- feat/fix/refactor/chore 등 커밋 타입별로 어떤 작업인지 파악
- 단순 커밋 나열이 아니라, 커밋들을 종합하여 "업무 단위"로 묶기
- 필요하면 변경된 파일도 확인하여 맥락 파악 (`git diff --stat <commit>`)

## 5단계: 보고서 작성

아래 형식으로 작성합니다. **구체적이고 결과 중심**으로 작성하세요.

```
# 주간업무보고서

## 기본정보
- 이름: 임상준
- 보고 기간: MM/DD(월) ~ MM/DD(금)

## 이번주 업무 내역 및 진행률

| 프로젝트 | 업무 내용 | 진행률 |
|---------|----------|-------|
| ... | ... | ...% |

## 이번주 업무 진행 결과 및 이슈사항

### 완료된 업무
- ...

### 진행 중인 업무
- ...

### 주요 성과 / 산출물
- ...

### 이슈 및 공유사항
- ... (없으면 "특이사항 없음")

## 이번주 업무 회고 및 지원 필요사항

### 회고
- ...

### 지원 필요사항
- ... (없으면 "특이사항 없음")

## 차주 업무 내역 및 목표 진행률

| 프로젝트 | 업무 내용 | 목표 진행률 |
|---------|----------|-----------|
| ... | ... | ...% |
```

## 작성 원칙

- 이 보고서는 개발자가 아닌 대표가 읽는 문서. 기술 용어(API, 리팩토링, 마이그레이션 등)를 쓰지 말고, 비개발자가 이해할 수 있는 비즈니스 용어로 번역하여 작성.
  - 예: "JWT 인증 미들웨어 리팩토링" → "로그인 보안 처리 방식 개선"
  - 예: "Prisma 마이그레이션 적용" → "데이터베이스 구조 변경 반영"
- "업무 진행 중", "확인 중" 같은 모호한 표현 금지. 무엇을 어디까지 했는지 구체적으로.
- 커밋이 없는 프로젝트는 제외
- 진행률은 커밋 내용과 브랜치 상태를 종합하여 추정
- 차주 업무는 진행 중인 업무의 연장선 + 열린 브랜치/PR 기반으로 추정
- 직전 주에 적었던 "차주 업무"·"진행 중인 업무"와 대조하여 연속성 유지. 같은 업무는 진행률 누적으로 표시 (60% → 90%)
- 회고는 기술적 관점에서 1~2줄로 간결하게

## 6단계: 파일 저장

작성된 보고서를 `/Users/pullim/Documents/workspace/주간업무보고/` 폴더에 마크다운 파일로 저장합니다.
- 파일명: `YYYY-MM-DD.md` (보고 기간의 금요일 날짜 기준)
- 폴더가 없으면 생성합니다

## 7단계: 검토

작성된 보고서를 보여주고, 수정이 필요한 부분이 있는지 확인합니다.
