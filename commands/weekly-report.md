주간업무보고서를 작성해주세요. 아래 절차를 따릅니다.

## 1단계: 보고 기간 결정

- 인자가 있으면 해당 주를 기준으로 합니다: $ARGUMENTS (예: "2026-03-23" → 해당 주 월~금)
- 인자가 없으면 이번 주 월요일~오늘(또는 금요일) 기준으로 합니다
- 보고 기간을 "MM/DD(월) ~ MM/DD(금)" 형식으로 표시합니다
- **주말(토, 일) 작업은 그 다음 주 보고서에 포함합니다.** 즉, 이번 주 보고서의 수집 범위는 "직전 주 토요일 ~ 이번 주 금요일"입니다. (한국시간 KST 기준)

## 2단계: 직전 보고서 참고

`/Users/pullim/Documents/workspace/주간업무보고/` 폴더에서 가장 최근 보고서 파일(`YYYY-MM-DD.md` 중 최신)을 읽어 다음을 파악합니다.

표만 훑지 말고 **본문 전체를 줄 단위로** 읽습니다. 대조 규칙은 `## 작성 원칙`의 "직전 보고서 대조"를 따릅니다.

- 직전 주의 "차주 업무 내역" — 이번 주에 실제 어떻게 진행됐는지 대조
- 직전 주의 "진행 중인 업무" — 이번 주에 완료·지속·중단 중 어느 상태인지 확인
- 대조 항목과 처리 방법은 `## 작성 원칙`의 "직전 보고서 대조"를 따릅니다

폴더가 비어있거나 파일이 없으면 이 단계를 건너뜁니다.

## 3단계: Git 이력 수집

아래 workspace 내 모든 git 프로젝트에서 보고 기간의 커밋을 수집합니다.
각 프로젝트 디렉토리에서 병렬로 실행하세요:

```
TZ=Asia/Seoul git log --author="sangjun-lim" --since="<직전 주 토요일>" --before="<이번 주 토요일>" --format="%h %ad %s" --date=short
```

대상 디렉토리: /Users/pullim/Documents/workspace/ 하위의 모든 git 저장소

## 4단계: 커밋 분석 및 업무 분류

수집된 커밋을 분석하여 다음 기준으로 업무를 분류합니다:
- 프로젝트별로 그룹핑
- feat/fix/refactor/chore 등 커밋 타입별로 어떤 작업인지 파악
- 단순 커밋 나열이 아니라, 커밋들을 종합하여 "업무 단위"로 묶기
- 필요하면 변경된 파일도 확인하여 맥락 파악 (`git diff --stat <commit>`)

## 5단계: 보고서 작성

아래 형식으로 작성합니다. **짧고 결과 중심**으로 작성하세요 — 구체성은 설명이 아니라 숫자로 확보합니다.

```
# 주간업무보고서

## 기본정보
- 이름: 임상준
- 보고 기간: MM/DD(월) ~ MM/DD(금)

## 이번주 업무 내역 및 진행률

| 프로젝트 | 업무 내용 | 진행률 |
|---------|----------|-------|
| ... | ... | ...% |

## 이번주 업무 진행 결과 및 이슈사항

### 완료된 업무
- ...

### 진행 중인 업무
- ...

### 주요 성과 / 산출물
- ...

### 이슈 및 공유사항
- ... (없으면 "특이사항 없음")

## 이번주 업무 회고 및 지원 필요사항

### 회고
- ...

### 지원 필요사항
- ... (없으면 "특이사항 없음")

## 차주 업무 내역 및 목표 진행률

| 프로젝트 | 업무 내용 | 목표 진행률 |
|---------|----------|-----------|
| ... | ... | ...% |
```

## 작성 원칙

### 용어

- 이 보고서는 개발자가 아닌 대표가 읽는 문서. 기술 용어(API, 리팩토링, 마이그레이션 등)를 쓰지 말고, 비개발자가 이해할 수 있는 비즈니스 용어로 번역하여 작성.
  - 예: "JWT 인증 미들웨어 리팩토링" → "로그인 보안 처리 방식 개선"
  - 예: "Prisma 마이그레이션 적용" → "데이터베이스 구조 변경 반영"
- "업무 진행 중", "확인 중" 같은 모호한 표현 금지. 어디까지 갔는지는 **숫자로** 쓴다(건수·비율·기간). 단, 외부 서비스 사실 관계는 아래 "사실 검증"을 따른다.

### 분량

- 표의 `업무 내용`: **한 줄.** 업무명 + 결과 수치까지만.
- `완료된 업무` 각 항목: **1~2문장.** 원인 분석, 동작 방식, 조치 경위는 쓰지 않는다. 숫자(규모·건수·개선폭)는 남기고 설명을 뺀다.
- `진행 중인 업무` 각 항목: **1문장** + 하위 불릿 최대 4개(각 1줄).
- `주요 성과 / 산출물`: 산출물명만 나열. `완료된 업무`에 쓴 내용을 반복하지 않는다.
- `이슈 및 공유사항`, `지원 필요사항`: 각 항목 **1줄.**
- 회고: **1줄.**

### 항목 선별

- 대표의 의사결정·비용·일정에 영향이 없는 자잘한 수정은 넣지 않는다.
- 커밋이 없는 프로젝트는 제외.
- 운영 장애가 여러 건이면 표에서는 한 행으로 묶고, 개별 내용은 `완료된 업무`에서만 나눈다.

### 직전 보고서 대조

2단계에서 읽은 직전 보고서 본문과 줄 단위로 대조한다.

- 대조 항목: 직전 주에 쓴 수치, 플랫폼/대상 개수, 업무명, 진행률. 톤이 직전 주와 다르면 직전 주에 맞춘다.
- 개수가 같아도 구성이 바뀌었으면 그 사실을 명시한다(예: "대상 3곳 유지, 구성 변경 — A 제외·D 추가").
- **직전 주 "이번주 업무 내역" 표에서 100%로 마감 보고한 업무는 업무 항목(양쪽 표·`완료된 업무`·`진행 중인 업무`)으로 다시 넣지 않는다.** 후속 작업이 있었어도 마찬가지. 직전 주 *차주* 표의 목표 진행률 100%는 해당하지 않는다 — 이번 주에 실제로 마감했다면 정상적으로 보고한다.
- 직전 주 서술과 이번 주 결론이 다르면(진단 번복, 효과 재평가, 재발 등) 정정 사실을 반드시 밝힌다. 조용히 바꾸지 않는다. 위 규칙으로 업무 항목에서 빠지는 건이라도 정정은 남긴다.
- **구성 변경·정정·진행률 급등 근거는 `이슈 및 공유사항`에 각 1줄로 적는다.** 표 셀과 `완료된 업무` 문장에는 넣지 않는다.

### 사실 검증

- 외부 서비스의 수수료·정책·기능 지원 여부는 **확인한 것만 단언**한다. 확인 못 했으면 "확인 필요"로 쓴다. 홍보 문구·슬로건을 결론처럼 옮기지 않는다.

### 진행률

- 커밋 내용과 브랜치 상태를 종합해 추정한다.
- "이번주 업무 내역" 표는 직전 주 대비 **증분**으로 쓴다(60% → 90%). 신규 업무는 단일 값, 차주 표는 목표 단일 값.
- 한 주에 **30%p 이상** 올릴 때는 근거를 `이슈 및 공유사항`에 1줄 적는다.
- 차주 업무는 진행 중인 업무의 연장선 + 열린 브랜치/PR 기반으로 추정.

## 6단계: 파일 저장

작성된 보고서를 `/Users/pullim/Documents/workspace/주간업무보고/` 폴더에 마크다운 파일로 저장합니다.
- 파일명: `YYYY-MM-DD.md` (보고 기간의 금요일 날짜 기준)
- 폴더가 없으면 생성합니다

## 7단계: 검토

작성된 보고서를 보여주고, 수정이 필요한 부분이 있는지 확인합니다.
