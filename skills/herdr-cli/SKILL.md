# Herdr CLI

Use `hc` for running programs and coordinating agents; use `herdr-app` for the visible window.
Read `hc --skill` before coordinating terminals, and `herdr-app --skill` before changing spaces or panes.
For interface settings, read `~/.config/herdr-app/AGENTS.md`; it is generated by the installed app.

## Runtime routing

When `HC_TERMINAL_ID` is set, this session runs in Herdr. Use this workflow instead of the Orca-specific terminal, dispatch, and worktree procedures in other personal skills. Explicit requests to operate Orca still use `orca-cli` against the named Orca resource.

- Preserve the task's chosen checkout and isolation decision. With no decision, use the current checkout when isolation is unnecessary; ask only when the choice materially changes the result. Use one writing worker per checkout.
- For an isolated checkout, inspect `git worktree list` and the repository's default branch. Reuse an assigned worktree, or create a new Git worktree from the intended base. Show it with `herdr-app do space.new --name <name> --folder <absolute-path>` when the user wants a visible workspace. A space alone does not create a Git worktree.
- Keep the existing model, role, review, and approval rules in `CLAUDE.md`. Built-in `Agent` workers still use their agent definitions. For a separately launched worker, use `hc run --bg --cwd <checkout>` with the selected agent, exact scope, and first task. Use the installed manuals for reporting, waiting, and cleanup. The supervisor reviews the actual result.
- Full handoffs transfer ownership: add `--outlive-parent` to `hc run` so closing the original terminal does not terminate the handed-off work. After confirming delivery, report the terminal and checkout without monitoring. Supervised work keeps the default parent lifetime and the supervisor's responsibility for integration and completion.
- Runtime failures do not authorize falling back to a different app or checkout. Inspect the failed command and preserve running work.

## Existing personal setup

Claude Code uses `~/.claude` directly, including instructions, skills, commands, hooks, memory, and session history. Keep that source of truth; do not copy it to a separate Herdr profile.

- The app's `programs.json` contains the user's launch options. Preserve those options when creating equivalent agent tabs; do not change hook approvals or project trust.
- For prior conversations, use Claude Code's `/resume` or the app's “Claude Code · 기존 대화 선택” entry in the matching project folder. Do not resume a conversation that is still running in Orca; leave it there until the user finishes or closes it.
- For browser tasks, use Claude in Chrome when connected. Herdr has no Orca browser page IDs or web view. Use `orca-cli` only for an explicit request about Orca's existing browser.
- Usage remains in the existing Claude Code status line and `/usage`. Herdr's agent list reports activity, not subscription quota.
